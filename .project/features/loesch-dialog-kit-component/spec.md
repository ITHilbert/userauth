# Spec loesch-dialog-kit-component (#2449)
Risiko: normal — ersetzt Markup und Skript des Lösch-Dialogs der drei Verwaltungslisten durch die Kit-Component; Ziel-Routen und Löschlogik im Backend bleiben unverändert. Neue Asset-Routen liefern nur zwei statische Kit-Dateien (kein Nutzerinput, Whitelist).
Art: Refactoring (Folge aus #2439; laravel-kit 1.14.0 liefert die Component mit Sprachdateien, #2451)
Status: freigegeben (Task #2449 `freigabe`; Antwort Torrent-Admin: userauth liefert die Kit-Module selbst aus, Component per Sprachdateien übersetzt; Moderator selbst im automode)
Rückbau: entfällt (kein Übergangsstand)

## Akzeptanzkriterien
- **AK1** Gegeben die Listen Benutzer, Rollen, Rechte (Theme `kern`, Sprache `de`), Wenn sie gerendert werden, Dann steht der Dialog aus `<x-kit::dialog-delete>`: Wurzel `[data-kit-delete-dialog]` mit `data-route` = Lösch-Route mit ID 0 der jeweiligen Liste (`user.delete`, `role.delete`, `permission.delete`), Überschrift mit dem bisherigen Titel („Benutzer löschen“ usw.) und dem bisherigen Text, zwei Buttons „Abbrechen“ und „Löschen“ (Sprache `en`: „Cancel“, „Delete“), und genau ein Formular `#formDelete` (Methode POST, `_method=DELETE`, `_token`) — aus der Component, nicht aus dem Partial.
- **AK2** Gegeben die Listen aus AK1, Wenn gerendert, Dann enthält die Seite kein Inline-Skript mehr für den Lösch-Dialog (kein `data-kit-delete-bestaetigen`-Klick-Handler im Seitenquelltext, kein `routeMitId`), sondern genau ein `<script type="module">`, das `initLoeschDialog` aus der Asset-Route `userauth.assets.kit.loesch-dialog` importiert und aufruft.
- **AK3** Gegeben die Asset-Routen `userauth.assets.kit.loesch-dialog` (`userauth/assets/kit/loesch-dialog.js`) und `userauth.assets.kit.loeschen` (`userauth/assets/kit/loeschen.js`), Wenn sie abgerufen werden, Dann antworten sie mit 200, `Content-Type: text/javascript`, dem Inhalt der gleichnamigen Datei aus `js/` des Pakets laravel-kit, ohne Session-Cookie (Middleware-Gruppe `web` nicht angewendet, wie `userauth.assets.css`), mit `Cache-Control: public, max-age=300` (nicht `immutable`, weil Browser die relative Importadresse ohne Versionsparameter laden).
- **AK4** Gegeben die Asset-Routen aus AK3, Wenn eine andere Datei aus dem Kit-`js/`-Ordner (z. B. `mount-inseln.js`, `tabs.js`) oder ein Pfad mit `..` angefragt wird, Dann 404 — es gibt nur diese zwei Routen mit fester Whitelist, kein Dateiname-Parameter.
- **AK5** Gegeben das Partial `src/Resources/views/partials/loeschen.blade.php`, Wenn gelesen, Dann enthält es kein eigenes `<form id="formDelete"` und keinen `@push('userauth-scripts')` mit Klick-Handler mehr (nur die Component und das Modul-Skript aus AK2).
- **AK6** Gegeben `src/Resources/assets/css/userauth-verwaltung.css` (vorkompiliert, `npm run build:css`), Wenn gelesen, Dann enthält es Regeln für die feste Dialog-Ebene der Kit-Component: `.kit-dialog[hidden]` ist unsichtbar (`display:none`), `.kit-dialog:not([hidden])` liegt als feste, überdeckende Ebene (`position:fixed`, `inset:0`) mit zentriertem Inhalt; die Dialogbreite bleibt auf 32rem begrenzt. Die Quelle `resources-src/verwaltung.css` trägt dieselben Regeln.
- **AK7** Gegeben `composer.json` und README, Wenn gelesen, Dann verlangt `composer.json` `ithilbert/laravel-kit` `^1.14`; die README beschreibt den Lösch-Dialog als `<x-kit::dialog-delete>` mit Modul-Skript über die beiden Asset-Routen (Zeilen „Kit-Components und Skripte“, „Lösch-Buttons“, Upgrade-Hinweis Punkt 3 und Abschnitt zum Lösch-Dialog) und nennt, dass die Texte über die Sprachdateien des Kits kommen; der CHANGELOG hat einen Abschnitt `4.7.0` (#2449).
- **AK8** Gegeben das Verhalten im Browser (Fake-DOM-Test `tests/js/`), Wenn ein Lösch-Button der Liste (`data-kit-delete="5"`) geklickt und „Löschen“ bestätigt wird, Dann setzt `initLoeschDialog()` aus dem Kit die Action des `#formDelete` auf die Route mit ID 5 und sendet es; Abbrechen, Overlay-Klick und Escape schließen ohne Senden (die bisherigen Fälle der Datei `tests/js/loeschen-dialog.test.mjs`, jetzt gegen das Kit-Modul statt gegen das Inline-Skript).
- **AK9** Gegeben die bestehenden Tests der Verwaltung (`tests/Feature/AdminViewsKitTest.php`, `tests/Feature/KernDokuTest.php`, `tests/Feature/Nachbesserung/DialogDeleteTitelTest.php`, `tests/Feature/LoeschDialogTest.php`), Wenn sie laufen, Dann sind sie grün bzw. an die Component angepasst; jede Anpassung bleibt in der Aussage gleich (Dialog vorhanden, Titel/Text, Formular, kein Inline-Handler) und der test-writer zieht sie nach.

## Nicht-Ziele
Andere Seiten mit Lösch-Dialog, Theme-Unterstützung außer `kern` (die Verwaltung braucht `laravelkit.theme=kern`, wie bisher dokumentiert), Änderungen an laravel-kit.

## Entscheidungsspielraum
Auflösung des Kit-`js/`-Ordners (über die Datei des ServiceProviders des Kits), Namen der Controller-Methoden, Aufbau der Tests, CSS-Feinheiten im Rahmen von AK6.
