## Sicherheit
- Token-Prüfung: nur RS256-Schlüssel aus dem JWKS, Header-`alg` muss zum Schlüssel passen (`none`, HS256 mit öffentlichem Schlüssel im echten Lauf abgelehnt), unbekannte oder fehlende `kid` abgelehnt, `iss`, `aud` (Text/Liste), `exp` Pflicht mit 60 s, `nbf`/`iat` über php-jwt, `nonce` mit `hash_equals`, `sub` Pflicht.
- state/nonce: 32 Byte Zufall je Vorgang, in der Sitzung, vor jeder Prüfung per `pull` entnommen (einmal verwendbar, auch im Fehlerpfad, im echten Lauf nachgewiesen). Login-CSRF: Ein fremder Code ohne den state der eigenen Sitzung scheitert.
- Session-Fixation: `SessionGuard::login()` erneuert die ID (Test). Kein „Angemeldet bleiben“ bei OIDC.
- Open-Redirect: Ziel nur `intended` (vom Framework gesetzt) oder Config `redirect_after_login`; Guzzle mit `allow_redirects => false`, Timeouts gesetzt, Endpunkte nur aus der Discovery des konfigurierten Issuers.
- Kontoübernahme über E-Mail: nur genau ein aktiver Treffer, keine zweite `oidc`-Verknüpfung, gelöschte Konten werden nicht übernommen; offene Selbstregistrierung verliert Passwort und Remember-Token (AK20).
- 2FA-Verzicht nur im OIDC-Anwendungsfall (`ohneZweitenFaktor` hat genau einen Aufrufer).
- Ausgabe: Knopftext mit `{{ }}` escaped; Neuanlage per `forceFill` nur mit festen Feldern; Fehlermeldungen ohne Konfigurationswerte, Log ohne Geheimnisse (echter Lauf, grep).

## Funde: 1 muss, 0 sollte, 3 kann
- muss: Spec-Kopf ohne Zeile „Rechtegrenze: …“ trotz `Risiko: kritisch` — `abdeckung.php grenze` Exit 1. Inhaltlich ist die Grenze (Gast → angemeldet nur mit gültigem Token und eigenem state) durch echte Zugriffsversuche getestet (gefälschte Tokens, fremder state) und im echten Lauf bestätigt; es fehlt die Zeile, z.
