# Abdeckung: oidc-authelia (#2204)

Risiko kritisch. AK19: Schichtung über den bestehenden Test tests/Feature/SocialLogin/SocialLoginLayerDependencyTest.php: er prüft per Quelltext alle Dateien in src/Domain und src/Application auf Verweise auf Infrastructure, deckt also Application/Oidc automatisch ab; zusätzlich prüft OidcLoginSeiteTest::test_ak19, dass Port und Anwendungsfall in Application liegen und der Adapter aus Infrastructure kommt.
AK16/AK3: die Fehlermeldungen werden über die Sitzungsfehler (beliebiger Schlüssel) und die gerenderte Login-Seite geprüft, nicht über Wortlaut.

## Vorgaben an den Coder (aus den Tests, Klassennamen sonst frei)
- Port: ITHilbert\UserAuth\Application\Oidc\Contracts\OidcIdentityProvider mit isConfigured(): bool, authorizationUrl(string $state, string $nonce): string, fetchIdentity(string $code, string $nonce): OidcIdentity. Aus dem Container auflösbar (Tests lösen den Adapter über app(Port::class) auf).
- DTO: ITHilbert\UserAuth\Application\Oidc\OidcIdentity, Konstruktor mit benannten Argumenten subject, email, name (?string), groups (list von string), öffentliche readonly Eigenschaften gleichen Namens.
- Fehler: ITHilbert\UserAuth\Application\Oidc\Exceptions\OidcException (Konstruktor mit Meldung; Adapter wirft sie bei jedem Anbieterfehler, ungültigem Token, fehlender E-Mail, Userinfo-sub-Abweichung; Guzzle-Ausnahmen und InvalidArgumentException bei fehlendem CA-Bundle werden übersetzt).
- Anwendungsfall: ITHilbert\UserAuth\Application\Oidc\HandleOidcLogin (muss existieren, AK19).
- Guzzle-Clients: Der Adapter bezieht Clients ausschließlich aus dem Container über ITHilbert\UserAuth\Infrastructure\Oidc\OidcHttpClientFactory. Die Tests binden dort eine Fake-Fabrik, die das Interface implementiert: OidcHttpClientFactory MUSS ein INTERFACE sein (kein finale Klasse) mit make(array $options): \GuzzleHttp\ClientInterface. Der Dienst-Provider bindet es auf eine Guzzle-Implementierung. $options enthält verify (Pfad) wenn ca_bundle nicht leer ist, sonst keinen Schlüssel verify. Der Adapter ruft make je Anfrage oder je Vorgang neu auf und muss mit Exceptions aus dem Client umgehen (Fehlerstatus wirft bei Guzzle-Standard).
- Sitzungsschlüssel: userauth.oidc.state und userauth.oidc.nonce; beide nach dem Callback entfernt (auch bei Fehlern). Fehlerweiterleitung auf route('login', ['lokal' => 1]) mit withErrors (beliebiger Schlüssel), Fehlerarten im Log (Log-Ereignis MessageLogged, nie Geheimnisse, auch nicht über Guzzle-Exception-Texte mit Antwortinhalt).
- Der Adapter prüft Discovery bei jedem Aufruf (kein Cache); Discovery-URL <issuer>/.well-known/openid-configuration (issuer ohne und mit Schrägstrich am Ende robust).
- Das Fake in den Tests meldet für den Token-Aufruf den Request-Body als Form (parse_str); client_secret_post wie Spec.
- Tests setzen Config userauth.oidc.* zur Laufzeit; Prüfung enabled/konfiguriert zur Request-Zeit. Die Tests lassen kein Mail-Fake-Szenario für Bestätigungsmail zu: bei Verknüpfung per E-Mail darf SocialLinkConfirmation nicht verschickt werden und user_pending_social_links bleibt leer.
