## Sicherheit
- Asset-Routen ohne `web`: nur `GET|HEAD`, kein Routenparameter. POST antwortet 405. Der Pfad ist fest (`AuthAssetVersion::cssPath()` bzw. `verwaltungCssPath()`). Der Query-String wird ignoriert: `?v=../../.env` liefert dieselbe CSS mit 18657 Bytes. Fehlt die Datei, antwortet die Route 404 (`abort_unless(is_file…)`). Die Antwort enthält keine Session, kein CSRF-Token und keine Nutzerdaten, also wird nichts offengelegt.
- Durch das Verlassen der `web`-Gruppe fallen keine Sicherheits-Header weg: auch /login (mit `web`) setzt keine eigenen Header, Vergleich per curl.
- Die Middleware aller übrigen Paket-Routen ist unverändert, Liste unter AK13. Login, Rechteprüfung (`hasPermission`, `hasRole:admin`, `TwoFactorMiddleware`) und Impersonate laufen weiter durch `web` plus `auth`.
- Views: nur zusätzliche statische `div`-Wrapper, keine neue Ausgabe von Daten.
- `php .claude/hooks/abdeckung.php grenze packages/userauth/.project/features/kern-umstellung/spec.md` → Exit 0. Die Spec nennt `Rechtegrenze: entfällt` mit Begründung. Die neue Lage der Asset-Routen schafft keine Rechtegrenze, denn sie waren schon vorher öffentlich.
